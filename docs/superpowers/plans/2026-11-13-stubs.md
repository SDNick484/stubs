# Stubs Implementation Plan

> Each task is delivered as one Prompt issue run through issue-queue. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A self-hosted concert history (Flask + SQLite) where the owner imports his shows from a CSV, edits them by
hand, and browses them on a map with a year strip, by show, artist, venue, year and city, with an evidence trail.

**Architecture:** One Flask app in the public repo `SDNick484/stubs`. `app.py` holds the Flask object, auth, hooks
and every route; route-free logic lives in one sibling module per feature that takes a `sqlite3.Connection`. The
whole v1 schema and every setting land in Task 1, so later tasks add modules, routes and screens without touching
`db.py`, `settings.py`, `.env.example` or the installer. The frontend is a hash-routed SPA of native ES modules; show
panels and editor cards plug in through a registry so feature tasks don't edit each other's screens.

**Tech Stack:** Python 3.10–3.13, Flask 3, gunicorn, SQLite (WAL), PyJWT + cryptography (Cloudflare Access), pytest,
Playwright + Chromium (UI smoke), plain HTML/CSS/JS ES modules, `node --test`, Leaflet 1.9.4 + Leaflet.markercluster
1.5.3 (vendored), Alpine + OpenRC installer.

**Spec:** `docs/superpowers/specs/2026-11-13-stubs-design.md` (committed with this plan in Task 1).

## Constraints

**Language and versions**
- Python 3.10, 3.11, 3.12 and 3.13 on Ubuntu, and Alpine `latest` (production parity) in CI.
- Runtime Python dependencies are only Alpine packages: `py3-flask py3-gunicorn py3-jwt py3-cryptography`, plus
  `sqlite` (backup only). Everything else is the standard library (`urllib.request`, `html.parser`, `csv`, `json`,
  `ipaddress`, `socket`, `unicodedata`). No `requests`, no Pillow, no BeautifulSoup.
- Dev-only: `pytest`, `ruff==0.16.9`, `shellcheck-py==0.11.0.1`, `playwright` (UI smoke job only).
- No frontend framework, bundler or npm step. Native ES modules in `static/js/` with `static/js/package.json` =
  `{"type": "module"}`. Third-party JS only in `static/vendor/`, pinned, with version and licence in
  `static/vendor/README.md`.

**Checks that must pass** (run all before every commit; CI runs the same in jobs Lint, UI smoke, Python 3.10–3.13,
Alpine):

```sh
python -m pytest -q                                    # report the skip count and reasons
node --test tests/*.test.mjs
for f in static/js/*.js; do node --check "$f"; done
ruff check
shellcheck -s sh installer/setup-head.sh installer/build.sh ops/stubs-backup
sh installer/build.sh && sh -n dist/setup-stubs.sh
```

The UI smoke job runs `tests/test_*_ui.py` with Playwright at 412 px and fails on any skip.

**Never committed**
- The owner's real concert CSV or any row of it, real people's names, the owner's domain or hostnames, LAN addresses,
  container IDs, API keys, `data/`, `dist/`, `.env`.
- Tests use invented fixtures only: invented acts (The Paper Lanterns, Marigold Static, Cold Harbor…), invented people
  (Alex, Sam, Jordan, Riley), `concerts.example.com`, `192.168.1.100`.
- `.gitignore` ignores `*.csv` except `tests/fixtures/*.csv`; `tests/test_hygiene.py` fails on a tracked `.csv`
  outside `tests/fixtures/` and on the owner-identifier pattern (built from fragments, as in Matinee).

**Project-wide rules** (verbatim from the spec, sections 3, 6 and 12)
- Schema changes go through an idempotent `migrate()` and bump `SCHEMA_VERSION`. No manual DB step on the host.
- Writes live under `/admin/api/` with `@editor_required`; public reads under `/api/` with `@public_read`
  (403 `{"error": "Sign in to view"}` when `PUBLIC_VIEW=0` and not an editor).
- Public responses never carry: upcoming shows, notes, sources, confidence, companions, ratings, posters (unless
  `PUBLIC_POSTERS=1`), stubs, imports. A public request for an upcoming show's id is 404, never 403.
- Every response: `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `X-Content-Type-Options: nosniff`, and CSP `default-src 'self'; script-src 'self'; style-src 'self';
  img-src 'self' data: https://<TILE_URL host>; connect-src 'self'; object-src 'none'; base-uri 'none';
  frame-ancestors 'none'`. `Cache-Control: no-store` on `/api/` and `/admin/api/`.
- Escaping: every `${...}` that builds markup is exactly one call to `esc`, `fmtDate` or a `render*` function;
  `innerHTML` is only assigned a template literal, `""` or a `render*` call; no inline `<script>`/`<style>`,
  `style="..."`, `on*=`, `confirm(` or `alert(` in `static/js/`. `tests/test_frontend.py` scans for all of it.
- Errors are JSON `{"error": str}` via `common.ApiError(status, message)`. Bodies via `json_body()`; strings via
  `text(data, key, max_len)`; text over its limit is 400, never cut.
- Outbound HTTP sends `User-Agent: stubs/1.0 (concert history; https://github.com/SDNick484/stubs)` and a timeout;
  tests use recorded fixtures under `tests/fixtures/` and never touch the network.
- Conventional Commits, author `SDNick484 <SDNick484@users.noreply.github.com>`, one logical change each, on a
  feature branch merged by PR. Docs use OpenRC commands and say `vim`.
- Default port 8773; gunicorn binds `127.0.0.1`.

## Shared append points

These files are created in Task 1 and added to by many tasks. Add only inside your own task's marked section (Task 1
creates the markers), so parallel PRs touch different hunks.

| File | What a task adds |
|---|---|
| `app.py` | Its imports and routes, under `# ==== Task N: <name>` |
| `static/js/main.js` | Its `import` line and `route(...)` / `registerShowPanel(...)` / `registerAdminCard(...)` calls, under `// ==== Task N` |
| `static/style.css` | Its rules, under `/* ==== Task N */` |
| `tests/conftest.py` | Only helpers two or more test files use, appended at the end; prefer helpers inside your own test file |
| `tests/test_privacy.py` | A line in `PARAM_SAMPLES` only if a new public route uses a path parameter not already listed |
| `CLAUDE.md` | Its module in **Layout** and its task number in the **Status** line (`Built: Task 1, …`) |

`installer/build.sh` copies every top-level `*.py`, `static/` and `ops/`, so a new module needs no installer edit.
The UI smoke job runs `tests/test_*_ui.py` by glob, so a new UI test needs no CI edit.
